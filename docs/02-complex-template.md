## 1. 自定 Complex 型別

題目已經給了結構和乘法，你要補上其他運算。

### 1.1 先在紙上推公式

設 $`z_1 = a + bi`$、$`z_2 = c + di`$。

**試試看：** $`z_1 + z_2`$、$`z_1 - z_2`$ 的實部與虛部各是什麼？自己展開 $`(a+bi)(c+di)`$，推出題目給的乘法公式。

<details>
<summary>答案</summary>

```math
z_1 \pm z_2 = (a \pm c) + (b \pm d)\,i
```

```math
(a+bi)(c+di) = ac + adi + bci + bd\,i^2 = (ac - bd) + (ad + bc)\,i
```

關鍵是 $`i^2 = -1`$，所以 $`bd\,i^2`$ 變成實部的 $`-bd`$。

</details>

**試試看：** $`\dfrac{a+bi}{c+di}`$ 要怎麼變成「實部 + 虛部 $`i`$」的形式？分子分母同乘以什麼，可以讓分母變成實數？

<details>
<summary>答案</summary>

同乘分母的**共軛** $`c - di`$：

```math
\frac{a+bi}{c+di} = \frac{(a+bi)(c-di)}{(c+di)(c-di)} = \frac{(ac+bd) + (bc-ad)\,i}{c^2+d^2}
```

這就是題目同時要你寫 `conj` 的原因：除法可以寫成「乘以共軛，再除以 $`c^2+d^2`$」。

</details>

**想一想：** 除以 $`0 + 0i`$ 會發生什麼事？你要怎麼處理？

<details>
<summary>答案</summary>

$`c^2 + d^2 = 0`$，會除以 0，得到 `inf` 或 `nan`，而且不會有任何錯誤訊息。建議在除法裡先檢查分母，若為 0 就明確報錯（例如丟出例外，或印出訊息），不要讓 `nan` 悄悄流到後面的計算。

</details>

**想一想：** 模長 $`|z| = \sqrt{a^2 + b^2}`$。`abs_c` 應該回傳 `Complex` 還是 `double`？

<details>
<summary>答案</summary>

`double`。模長是一個非負實數，回傳 `double` 才能直接拿來比較大小、算誤差。

</details>

### 1.2 隱含轉換

題目的建構子是 `Complex(double r = 0.0, double i = 0.0)`。

**想一想：** 寫 `Complex z = 3.0;` 時，`z.re` 和 `z.im` 各是多少？為什麼可以這樣寫？那 `z + 1.0` 能編譯嗎？編譯器做了什麼？

<details>
<summary>答案</summary>

`z.re = 3.0`、`z.im = 0.0`。因為建構子可以只用一個 `double` 呼叫，而且沒有標 `explicit`，C++ 會把它當成「`double` → `Complex`」的隱含轉換。

`z + 1.0` 可以編譯（前提是 `operator+` 寫成接收兩個 `Complex` 的一般函式）：編譯器自動把 `1.0` 轉成 `Complex(1.0, 0.0)` 再相加。

延伸：如果把 `operator+` 寫成成員函式，`z + 1.0` 可以，但 `1.0 + z` 不行。這是運算子常寫成非成員函式的原因。

</details>

### 1.3 先測試 Complex 本身

**試試看：** 在接上 Horner 之前，先手算以下結果，再用程式驗證：$`(1+2i)(3+4i)`$、$`\dfrac{1+2i}{3+4i}`$、$`i \cdot i`$。

<details>
<summary>答案</summary>

- $`(1+2i)(3+4i) = 3 + 4i + 6i + 8i^2 = -5 + 10i`$
- $`\dfrac{1+2i}{3+4i} = \dfrac{(1+2i)(3-4i)}{25} = \dfrac{11 + 2i}{25} = 0.44 + 0.08i`$
- $`i \cdot i = -1 + 0i`$

</details>

**想一想：** 怎麼「驗證除法」比較聰明？

<details>
<summary>答案</summary>

若 $`q = z_1 / z_2`$，則 $`q \cdot z_2`$ 應該等於 $`z_1`$。乘回去比對即可，而且不需要事先知道答案。注意浮點數不要用 `==` 比較，要看差的模長是否小於一個很小的數（例如 $`10^{-12}`$）。

另外建議寫一個 `operator<<` 來印出 `Complex`，之後輸出表格會方便很多。

</details>

## 2. 範本版 Horner

題目已經直接給了範本程式碼。這一節的重點是**理解**它，而不是重寫它。

**想一想：** `a.back()` 是什麼？對應數學上的哪個係數？如果 `a` 是空的 vector，會發生什麼事？

<details>
<summary>答案</summary>

`a.back()` 是最後一個元素，也就是最高次係數 $`a_n`$，對應 Horner 的起點。

空 vector 呼叫 `back()` 是**未定義行為**，程式可能直接當掉，也可能回傳垃圾值。最好在函式開頭檢查並明確報錯。

</details>

**想一想：** 迴圈變數為什麼要先把 `a.size()` 轉成 `int` 再減 2？如果改用 `size_t k = a.size() - 2; k >= 0; --k`，會發生什麼事？

<details>
<summary>答案</summary>

`size()` 回傳的是**無號**整數（`size_t`），無號整數永遠 $`\ge 0`$：

- `k >= 0` 永遠成立，`k` 減到 0 之後再 `--k` 會繞回一個超大的數，變成**無窮迴圈**或越界存取。
- 若 `a.size()` 是 1，`a.size() - 2` 也會繞成超大的數。

先轉成 `int`，`(int)a.size() - 2` 在 size 為 1 時是 $`-1`$，迴圈就不會執行，結果正確。

</details>

**想一想：** 範本裡用到了 `T` 的哪些運算？你的 `Complex` 都有提供嗎？用同一個 `horner` 分別傳入 `std::vector<double>` 和 `std::vector<Complex>`，編譯器在背後產生了幾份函式？

<details>
<summary>答案</summary>

用到：複製（`T result = ...`）、`*`、`+`、指定（`=`）。只要 `Complex` 有重載 `*` 和 `+` 就夠了（複製與指定由編譯器自動產生）。

編譯器會產生**兩份**函式：一份 `T = double`、一份 `T = Complex`。範本是「產生程式碼的模具」，用到哪種型別就產生哪一份。

</details>

## 3. 正確性驗證：e 的複數次方

```math
E_n= \sum_{k=0}^{n} \frac{z^{k}}{k!},\qquad z = 1 + \frac{\pi}{4}\,i
```

**想一想：** $`E_n`$ 的係數陣列長什麼樣？每個係數是實數還是複數？但陣列要宣告成什麼型別，`horner` 才能接受複數的 $`z`$？

<details>
<summary>答案</summary>

係數是 $`\left[\,1,\ 1,\ \tfrac{1}{2!},\ \tfrac{1}{3!},\ \ldots,\ \tfrac{1}{n!}\,\right]`$，數值都是**實數**。

但範本要求係數和 $`x`$ 是**同一個型別** `T`，所以陣列要宣告成 `std::vector<Complex>`（每個係數虛部為 0）。係數同樣可以遞推：$`c_k = c_{k-1} / k`$。

</details>

### 3.1 參考值

題目提示用 Euler 公式：

```math
e^{1+i\theta} = e\,(\cos\theta + i\sin\theta)
```

**想一想：** 為什麼參考值要用比 `double` 更精確的 `long double`？

<details>
<summary>答案</summary>

你要量的是 $`E_n`$ 的誤差，最小會到 $`10^{-16}`$ 左右。如果參考值本身也有 $`10^{-16}`$ 的誤差，你就分不出來是 $`E_n`$ 不準還是參考值不準。參考值的精度要明顯高於被測量的對象。

⚠️ 注意：在 **MSVC（Visual Studio）** 和 **Apple Silicon Mac** 上，`long double` 其實和 `double` 一樣是 64 位元，精度沒有提升。可以用 `sizeof(long double)` 檢查，並在報告中說明。

`long double` 版本的函式：`std::cos`、`std::sin`、`std::exp` 都有接受 `long double` 的多載，傳入 `long double` 參數就會自動選到（也可以用 `cosl`、`sinl`、`expl`）。

</details>

**想一想：** 「誤差」要怎麼定義？實部和虛部分開看，還是用 $`|E_n - \text{參考值}|`$？

<details>
<summary>答案</summary>

- **模長** $`|E_n - \text{參考值}|`$：一個數字就能代表「離真值多遠」，適合畫收斂表格。
- **實部、虛部分開**：可以看出誤差主要來自哪一部分，也能和第一題的 $`\cos(\pi/4)`$、$`\sin(\pi/4)`$ 對照。

兩者都印出來最完整。

</details>

### 3.2 觀察

**想一想：** $`n`$ 從 1 到 20，誤差怎麼變化？大約從哪個 $`n`$ 開始不再下降？和第一題的 $`\sin(\pi/4)`$ 比，哪個收斂得比較快？為什麼？

<details>
<summary>答案</summary>

誤差穩定下降，大約在 $`n = 18 \sim 20`$ 降到 $`10^{-16}`$ 左右後停住（數量級參考：$`n=10`$ 約 $`10^{-7}`$，$`n=15`$ 約 $`10^{-12}`$）。

$`\sin(\pi/4)`$ 在 $`n \approx 7`$ 就到極限，收斂快得多，原因有兩個：

1. $`\sin`$ 第 $`n`$ 項的分母是 $`(2n+1)!`$，$`e^z`$ 只有 $`n!`$。同樣的 $`n`$，$`\sin`$ 其實已經走到級數的第 $`2n+1`$ 次方。
2. $`|z| = \sqrt{1 + (\pi/4)^2} \approx 1.27`$，比 $`\pi/4 \approx 0.785`$ 大，分子 $`|z|^k`$ 衰減得比較慢。

</details>

## 4. 問題延伸

### 4.1 實係數 + 複數 x

**試試看：** 呼叫 `horner(一個 std::vector<double>, 一個 Complex)`，編譯，**把錯誤訊息完整讀一遍**。錯誤訊息說 `T` 被推導成什麼？

<details>
<summary>答案</summary>

錯誤訊息大意是 *deduced conflicting types for parameter 'T' ('double' and 'Complex')*：

- 從第一個參數 `std::vector<T>` 對上 `std::vector<double>`，推出 `T = double`
- 從第二個參數 `T` 對上 `Complex`，推出 `T = Complex`

兩個結論互相矛盾，所以推導失敗。

</details>

**想一想：** 題目說「範本在推導型別時並不會做轉換」。這和 1.2 節「`double` 可以隱含轉成 `Complex`」矛盾嗎？兩件事分別發生在哪個階段？

<details>
<summary>答案</summary>

不矛盾，兩件事發生在不同階段：

1. **範本參數推導**：編譯器要先決定 `T` 是什麼。這個階段只做「精確比對」，**不考慮**使用者定義的轉換（例如 `Complex` 的建構子）。
2. **函式呼叫**：`T` 確定之後，才會考慮把引數隱含轉換成參數型別。

第 1 步就失敗了，根本走不到第 2 步。而且就算 `T` 確定是 `Complex`，`std::vector<double>` 也不能自動轉成 `std::vector<Complex>`，它們是完全不同的型別。

</details>

**想一想：** 有哪些方法可以讓它運作？試著想至少兩種，並比較優缺點。

<details>
<summary>答案</summary>

1. **呼叫端轉換**：先把係數複製成 `std::vector<Complex>` 再呼叫。範本不用改，但每次都要多做一次複製。
2. **範本用兩個型別參數**：一個給係數型別、一個給 $`x`$ 的型別。這時要決定 `result` 的型別：它應該是「係數乘以 $`x`$」之後的型別（這裡是 `Complex`）。可以直接把 `result` 宣告成 $`x`$ 的型別，並用 `a.back()` 轉換成該型別來初始化；或是查 `decltype`、`std::common_type`，讓編譯器自動算出型別。這需要 `double * Complex` 這類混合運算能成立，而 `Complex` 的隱含轉換剛好能幫上忙。
3. **呼叫時明確指定 `T`**：`horner<Complex>(...)` 在這裡**不行**，因為 `std::vector<double>` 仍然轉不成 `std::vector<Complex>`。可以試試看，觀察錯誤訊息有何不同。

</details>

### 4.2 觀察「複可微」

設 $`P(z) = z^3 - z + 2i`$，$`z_0 = 1 + i`$，$`h`$ 是長度約 $`10^{-6}`$ 的複數。計算差商

```math
\frac{P(z_0+h) - P(z_0)}{h}
```

**試試看：** 寫程式**之前**先回答：$`P'(z_0) = 3z_0^2 - 1`$ 等於多少？沿實軸、虛軸、45° 方向的 $`h`$ 分別是什麼複數？$`P(z)`$ 的係數陣列是什麼？

<details>
<summary>答案</summary>

- $`z_0^2 = (1+i)^2 = 2i`$，所以 $`P'(z_0) = 6i - 1 = -1 + 6i`$。
- 三個方向的 $`h`$：
  - 實軸：$`10^{-6}`$
  - 虛軸：$`10^{-6}\,i`$
  - 45°：$`\frac{10^{-6}}{\sqrt{2}}(1 + i) \approx 7.07\times10^{-7}(1+i)`$
- 係數（由 $`a_0`$ 到 $`a_3`$）：$`[\,2i,\ -1,\ 0,\ 1\,]`$。注意常數項是**複數** $`0 + 2i`$。

</details>

**想一想：** 你預期三個方向的差商會一樣嗎？跑程式驗證。

<details>
<summary>答案</summary>

三者都非常接近 $`-1 + 6i`$，差異約在 $`10^{-6}`$ 量級（與 $`|h|`$ 同階，來自截斷誤差）。趨近方向不影響極限，這就是 $`P`$ 在 $`z_0`$ 複可微的意思。

</details>

**試試看：** 再對 $`f(z) = \bar z`$ 做同一件事。先手算：$`\dfrac{\overline{z_0 + h} - \overline{z_0}}{h}`$ 化簡後是什麼？和 $`z_0`$ 有關嗎？三個方向分別得到什麼？

<details>
<summary>答案</summary>

```math
\frac{\overline{z_0 + h} - \overline{z_0}}{h} = \frac{\bar h}{h}
```

和 $`z_0`$ 無關，**只和 $`h`$ 的方向有關**：

- 實軸：$`\bar h = h`$，得 $`1`$
- 虛軸：$`\bar h = -h`$，得 $`-1`$
- 45°：$`\dfrac{1-i}{1+i} = -i`$

三個方向得到三個不同的值，極限不存在。

</details>

**想一想：** 用一句話說明：為什麼 $`P(z)`$ 是複可微，而 $`\bar z`$ 不是？

<details>
<summary>答案</summary>

複可微要求差商的極限**與 $`h`$ 趨近 0 的方向無關**。多項式滿足這一點；$`\bar z`$ 的差商 $`\bar h / h`$ 會隨方向改變，所以 $`\bar z`$ 在任何一點都不是複可微。（實變函數只能從左右兩個方向趨近，複變函數卻有無限多個方向，所以複可微的要求嚴格得多，換來的就是「複可微即解析」這個強大的性質。）

</details>

**想一想：** 如果把 $`h`$ 改成 $`10^{-12}`$ 或 $`10^{-15}`$，差商會更準還是更不準？為什麼？

<details>
<summary>答案</summary>

**更不準**。參考數量級：$`|h| = 10^{-8}`$ 時誤差約 $`10^{-8}`$（最好），$`10^{-12}`$ 時約 $`10^{-4}`$，$`10^{-15}`$ 時已經錯到 $`10^{-1}`$。

差商的誤差有兩個來源：

- **截斷誤差**：約與 $`|h|`$ 成正比，$`h`$ 越小越好。
- **捨入誤差**：$`P(z_0+h)`$ 和 $`P(z_0)`$ 非常接近，相減會發生第一題提過的**災難性抵銷**，誤差約 $`\varepsilon / |h|`$，$`h`$ 越小越糟。

兩者平衡在 $`|h| \approx \sqrt{\varepsilon} \approx 10^{-8}`$ 附近。

</details>
